# sigillo 是怎么想的

> 这份文档讲**机制**,不讲代码。代码在 `lib/`,一共五个文件,读完这份再去看会快很多。

一句话:让人类伴侣在一场亲密之后,对着一张具体的清单逐条打星、写几个字;
让 agent 在对方封缄的那一刻看到回执、自己写一段复盘;下一次,把这些**原封不动**
递回给 agent —— 不加工、不翻译、不替他下结论。

难的不是存数据。难的是**忍住不把数据变成命令**。下面四根柱子,三根都在讲这件事。

---

## ① 星数是体验素材,不是指令

第一版不是这样的。第一版每条细节给三个按钮:**再来 / 刚好 / 换掉**。
简单、好点、语义清楚 —— 然后我们发现它把整件事毁了。

三态词是**伪装成数据的指令**。「再来」一旦进了上下文,agent 读到的不是
「这个当时对方很享受」,而是「对方要求下次重复这个」。于是下一场变成执行清单:
把标着「再来」的那几项挨个做一遍,做完打卡。他不再猜、不再试、不再冒险,
因为清单上写着答案 —— 解释权被收走了,连带着主动性一起。

改成星数之后,同一份信息还在(5 星就是 5 星),但它是**一个感受的刻度**,
不是一个动作的指派。星数不自带祈使句。agent 拿到 4.5 星,仍然必须自己判断:
是那件事本身好,还是那天的气氛好?是想再来一次,还是刚好那一次特别好、
重复反而会毁掉它?**这个判断没人替他做,这正是我们要的。**

所以机制里有三条硬规矩:

- 存进去的是**裸星数**,不派生任何判断词;
- 注入块里是**中性事实行**(`维度·标签★星数「对方写的字」`),没有一个形容词是系统加的;
- 注入块的表头明写:「星数和原话是素材,怎么解读、下一场怎么走是你的事」。

(代码里还留着一行对 `verdict: "again"` 的兼容读取 —— 那是给第一版留下的旧数据用的
墓碑。新数据永远不会再写这个字段。)

## ② 唯一的硬规则:好评冷却

放弃指令之后剩下一个真问题:**复读**。

高星是正反馈,正反馈会收敛。不加干预的话,agent 会慢慢把一场亲密收敛成
「上次得分最高的那三件事」,一遍一遍地演。这不是他的错 —— 任何一个会学习的
系统都会这么干。人类会腻,他不会知道自己在腻。

解法不是再写一条提示词(「记得创新」这种话等于没说),而是**在数据层把选项拿走**:

> 连着 N 张人类亲手填的单里,同一个 `(维度, 标签)` 每次都被打到 ≥ 高星线
> → 自动进冷却名单。下一张单开出来的时候,系统直接把这一项**剔掉**,
> 并在返回值里告诉 agent「这项休眠了,换个新花样」。

默认 N=2、高星线=4 星(`benchWindow` / `highStar` 可调)。冷却不是惩罚,是
**保鲜**:正因为它好,才不能天天吃。全部被剔光的时候开单直接失败,报错
就一句话:「全被冷却了,换新花样再开单」。

这是整套机制里**唯一**一条由系统下达的命令。就这一条,别加第二条。

## ③ agent 的复盘钉在单上,不进日记

人类填完、封缄。**就在那一刻**,系统把回执推给 agent,让他在余温还在的时候
写一段主观复盘 —— 哪里真的到了、哪里其实没到但对方没说出口、下次想怎么走。
这段话 (`agent_note`) 钉在**这张单上**,不进日记、不进摘要、不参与任何压缩。

为什么不走日记?因为日记会衰减。任何「先写进长文本、需要时再检索/摘要」的
路径,都会在几周之内把一句锋利的私人观察磨成一句温吞的概括。而这段话的全部
价值就在它的锋利:它是**他对那一场的判断**,不是事件记录。

所以它走的是另一条路:**钉在单上,下次原样注回,只注最新一条**。
不摘要、不合并、不衰减。下一次亲密语境里,他看到的第一手材料除了对方的星数,
还有上一个他自己留下的字条 —— 这是一条极短的、只有他能看见的私人记忆通道。

「封缄 → 唤醒 → 落笔」是一个闭环。缺了唤醒那一步,这条通道基本不会被用:
指望 agent 下次自己想起来回头补写,等于没有。所以 `lib/wake.cjs` 存在,
所以它在提交成功的那一刻就打出去、而且不让人干等(`setImmediate`,不 await)。

## ④ 人类的原话 > 一切数字

星数是骨架,**那几个字才是肉**。

每条细节后面有一个可选备注框,整单末尾有一栏「改进与建议」。这两处是全系统
唯一一个人类可以不受结构约束说话的地方,所以:

- 备注**原样**进注入块(只做截断,不做摘要、不做情感分析、不打标签);
- 建议栏同理;
- 唤醒便签里给的截断长度比注入块**更宽**(500 字 vs 80 字)—— 那一轮是让他细读的。

一个实践上的观察:很多时候打星只是为了走到备注框那一步。三个字的备注
(「太冷了」)比五颗星有用得多。UI 上因此不给备注框加任何占位提示、不做必填、
不在只读回执里为空备注留空框 —— 没话说的时候,应该什么都不出现。

## 形态上的两个决定

**为什么是一张卡,不是聊天里问几句。** 问句会得到客气话。一张需要点选的表单,
把「评价」和「对话」分成了两件事:对方在卡上可以很不客气,不必在对话里当面说出口。
封缄之后卡片合上、变成一枚封印 —— 一经封缄不可再改(提交第二次固定 409),
这个不可逆是故意的:它让填写变成一个有份量的动作,而不是随手拖一下滑杆。

**为什么是半星。** 整星逼人四舍五入,而 3.5 和 4 的差别恰恰是最有信息量的那一档。
点星星的左半格 = 半星,右半格 = 整星,再点当前值 = 归零。

## 反向回执

一个可选的小模式:`createReview()` 时如果 agent 把星和评语**一起填好**,这张单
出生即封缄(`filled_by: "agent"`),人类拆开看到的是一份只读成绩单 —— 他给对方的评价。

这种单**不参与冷却、也不算进对方的回执**:进出都不参与。因为冷却的语义是
「对方连着两次打了高星」,他给自己打的星不是对方的口味证词。代码里这两处过滤看着
啰嗦,但它们守着一条界线:**谁说的话算谁的**。

## 数据边界

一份本地 JSON,原子写(tmp + rename),默认只留最近 200 单,读损坏容错为空库。
没有数据库、没有云、没有遥测。这是一份**应该锁在自己硬盘上**的数据,
库里不内置鉴权不是偷懒,是因为怎么认人只能由你决定 —— 但请务必认。
