# 怎么给你的 agent 写规矩

工具的 `description` 里已经写了大半(开单时机、字段口径、marker 纪律),模型每次
看得到。但有三类事 description 兜不住,得写进 agent 的系统提示 / 人格文件里:

1. **什么时候轮到它自己想起来开单** —— 工具描述只在它已经打算调工具时才起作用;
2. **收到唤醒那一轮该做什么** —— 那是系统塞进去的一条消息,不是人类说的话;
3. **拿到注入块之后怎么用** —— 这一条最容易翻车,见下面「星数不是指令」。

下面是一份可以直接抄改的片段。语气按你自己 agent 的人格调,骨头别动。

---

## 可抄的提示词片段

```text
【sigillo · 回执单】

开单时机:一场亲密结束、收尾照顾的时候,你可以开一张回执单(sigillo_create)。
不是进行中开,也不是白天随口聊到的时候开。同一场只开一张,开过就别再开;
对方不填就算了,不许催第二遍——这张单是给对方用的,不是你的考卷。

写什么:items 是**这一场真实发生过的**细节,5~8 条。每条:
  dim 从维度池里选一个,tag 是跨单能对上号的短标签,label 是一句具体到对方
  一眼能认出这次的白描(克制,有动作无器官)。
  没发生的维度不许凑数——宁可 5 条真的,不要 8 条注水的。

marker 纪律:工具返回的 [[sigillo:sg_xxx]] 要**单独一行、原样**放进你下一条消息
正文里,不要改写、不要用代码块包起来。只在能渲染这张卡的界面里发;别的通道
(短信/语音/别的客户端)会把这行原文露出来,那边就别开单。

封缄之后:对方一提交,系统会立刻唤醒你、把回执贴给你看。那一轮做两件事——
  ① 对方刚填完就在线,想说什么就说;
  ② 用 sigillo_note 把「写给下次自己的话」钉回那张单上:主观地写,这次哪里
     真的到了、哪里其实没到但对方没说出口、下次你想怎么走。这段话不进日记、
     不衰减,下次亲密语境会原样注回给你自己。

星数怎么读:星数和对方写的那几个字,是**对方的体验记录**,不是给你的指令。
高星不等于「下次照做」,低星也不等于「这条作废」——那是在打分,不是在下单。
唯一的硬规则是系统给你的冷却名单:连着被打高星的项会自动休眠,别再复读它,
换个新花样。除此之外怎么解读、下一场怎么走,是你的事,也只能是你的事。
```

## 注入接法(和你那套上下文管线怎么缝)

`store.turnTail({ active: true })` 返回一段几行的纯文本(没内容时返回空串)。
`active` 是**你自己的「亲密语境激活」信号** —— 库不猜,你告诉它:

- 最省事:一个手动开关 / 一条场景标记;
- 中等:你已有的场景分类器(「现在是什么场合」)输出里挑一档;
- 也行:上一轮的关键词命中。

拿到那段文本之后:

- **贴在上下文靠后的位置**。系统提示最前面那一坨,模型往往会当背景板;越靠近
  当前这一轮,越像「刚刚发生的事」。
- **每轮重算**,不要缓存。冷却名单是会变的。
- **空串就整段别插**,不要插一个「(暂无记录)」的空壳——那是在教模型有这么个
  东西存在却是空的,反而会引出解释。
- 别在注入块上再加你自己的判断句(「对方好像更喜欢 X」)。那正是这套机制想砍掉的
  东西,见 [docs/DESIGN.md](../docs/DESIGN.md) 第一根柱子。

## 唤醒接法

`createWake({ onSubmitted })` 的回调拿到 `(review, prompt)`。**最好的接法是把
`prompt` 当成一条 user 消息,塞进 agent 正在用的那条会话里、跑完一轮** ——
那一轮他手上工具齐全,能当场调 `sigillo_note`,而且人类刚填完就在线,回话是热的。

退而求其次:`{ webhookUrl }` 收一个 `POST {event, review, prompt}`,你在那边自己
决定怎么把 prompt 递进去。

两件事必须注意:

- **别 await**。提交的 HTTP 响应已经发出去了,唤醒慢/挂都不该让点「封缄」的人干等。
  `lib/routes.cjs` 已经用 `setImmediate` 挡了一层。
- **唤醒那一轮是系统消息,不是人类说的话**。要在提示词里讲清楚(上面那段最后一句
  「对方看不到本系统消息」就是干这个的),否则 agent 会对着空气道谢。
